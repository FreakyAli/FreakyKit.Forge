# Real-World Benchmark Sources Index

Flat, machine-readable index of every scenario in this project. Each entry links to a
`Scenarios/<Domain>.md` file with full provenance, design notes, and fixture rationale.

## Attribution model

Types in this project are **not extracted verbatim from any single repository**. The shape of
each scenario is hand-built to match the patterns found in real production-grade open-source
projects (and in commercial APIs with publicly documented schemas). Per-scenario docs name the
specific inspirations.

This hybrid attribution means:

- No licence-extraction risk (we're not copying anyone's code)
- The shapes are still anchored in concrete real-world systems
- A sceptic can verify the patterns against the cited references
- We can update or extend scenarios without re-checking upstream licences

## What the benchmarks compare

Every scenario benchmarks the same six implementations, in the same order:

1. **Hand-written** — pure C# property assignments, the baseline Forge must match
2. **Forge** — generated by `FreakyKit.Forge.Generator` (this repo)
3. **Mapperly** — `Riok.Mapperly` 4.3.1 source generator
4. **AutoMapper** — `AutoMapper` 16.1.1 reflection-based
5. **Mapster** — `Mapster` 7.4.0 expression-tree based with caching
6. **Facet** — `Facet` 5.8.2 source generator

Each scenario is shaped to stress a different production-realistic mapping pattern. The point
is not to find "the fastest mapper" — it's to show how each library handles real shapes that
synthetic micro-benchmarks miss.

## How to reproduce

```bash
# From the repo root, run all 8 scenarios:
dotnet run -c Release --project benchmarks/FreakyKit.Forge.Benchmarks.RealWorld -- -f '*'

# Or a single scenario:
dotnet run -c Release --project benchmarks/FreakyKit.Forge.Benchmarks.RealWorld -- --filter '*B2BOrderFulfilment*'

# List available benchmarks without running:
dotnet run -c Release --project benchmarks/FreakyKit.Forge.Benchmarks.RealWorld -- --list flat
```

BenchmarkDotNet writes results to `BenchmarkDotNet.Artifacts/results/` next to the project.
Run on a machine with no other CPU load for stable numbers.
